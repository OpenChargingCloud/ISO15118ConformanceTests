# Task: replace SAP seed vectors with cbV2G reference output (Phase 0)

## Context

You're working in the repo `D:\Coding\OpenChargingCloud\Vanaheimr.V2G.Exi` — a .NET 10 library
intended, long-term, to parse and serialize ISO 15118-2 and 15118-20 EXI messages.
Current state:

- `WWCP_ISO15118_EXI/` — BitReader/BitWriter, ExiPrimitives, V2GTP header, and a
  hand-written codec for SupportedAppProtocolReq/Res (SAP).
- `WWCP_ISO15118_EXI_SourceGenerator/` — Roslyn generator (XSD → codec), secured by a diff test
  against the hand-written codec.
- `WWCP_ISO15118_EXI_Tests/` — NUnit, vector-driven, 71 tests green (`dotnet test -c Release`).

**The problem you're solving:** the vectors in
`WWCP_ISO15118_EXI_Tests/Vectors/AppProtocol.vectors.json` were generated by the codec itself.
Green only proves internal consistency — not that the bytes match what a real EVSE expects on
the wire. The planned workflow is already written up in
`WWCP_ISO15118_EXI_Tests/Vectors/REPLACING_SEED_VECTORS.md` — read it first, it is
authoritative. Also read: `README.md`, `AppProtocol/SupportedAppProtocolCodec.cs`,
`Tests/Infrastructure/`, and the vector file itself.

## Goal

Every SAP vector carries `expectedHex` from **libcbv2g** (EVerest, Apache-2.0,
https://github.com/EVerest/libcbv2g) at a pinned commit. After that, every test failure is a
real conformance finding against a production reference implementation.

## Steps

### 1. Build the reference CLI (`tools/cbv2g-ref/`)

- Clone libcbv2g, pin a specific commit (note the SHA).
- Write a small C program that wraps libcbv2g's app-handshake codec
  (module `app_handshake`, functions like `encode_appHand_exiDocument` /
  `decode_appHand_exiDocument` — look up the exact API in the repo):
  - `encode`: reads our vector file's `input` JSON format from stdin
    (preferred; alternatively a deliberately simple line/argument format if JSON parsing
    in C is disproportionate — the driver script then takes over the translation),
    writes the EXI stream as hex to stdout.
  - `decode`: reads hex from stdin, writes the field values as JSON to stdout.
- Important: our vectors contain the complete EXI stream **including the header byte
  0x80**, but without the V2GTP header. Check what libcbv2g produces and align the convention.
- Build: CMake. On this Windows 11 machine, Git Bash and PowerShell are available;
  take the path of least resistance (MSVC Build Tools, MSYS2, or WSL — whatever
  is available and works). The test suite run itself stays independent of this:
  the tests only read the checked-in JSON file, the CLI is only needed for
  (re-)generation.
- Put build and usage instructions under `tools/cbv2g-ref/README.md`.

### 2. Driver script for regeneration

- A script (PowerShell or Python) under `tools/` that pipes every vector from
  `AppProtocol.vectors.json` through the CLI and replaces `expectedHex` in the file.
- Write the `referenceEncoder` field into the vector file, exactly as suggested in
  `REPLACING_SEED_VECTORS.MD` (name, repo, commit, buildFlags).
- Remove the `generatorNote` self-encoding warning, set `generator` to `cbV2G@<sha>`.

### 3. Close vector gaps (add these before regenerating)

Add the cases listed in `REPLACING_SEED_VECTORS.md`:
- all three ResponseCode values × {SchemaID present, absent},
- request with 20 entries (Req_20 path: 0-bit terminator),
- request with exactly 1 entry,
- Priority at the boundaries 1, 2, 19, 20,
- ProtocolNamespace near maxLength=100,
- non-ASCII characters in the namespace (umlauts + at least one non-BMP code point,
  e.g. an emoji — exercises multi-byte runes).

### 4. Diff and fix

- `dotnet test -c Release`. Every mismatch is now meaningful: presumably a bug
  in the C# codec relative to the reference. Analyze with the bit diff from `HexUtil`,
  fix the root cause in the C# code (the hand-written codec AND the source-generator
  emitter must stay consistent — the `GeneratedCodecDiffTests` secure that).
- **Explicitly report every divergence found in the closing report** (what was wrong,
  in which bit field, how it was fixed). If there are no divergences, that's an
  excellent result — but only claim it after a complete run.
- Check bidirectionally: bytes we encode must be decodable by cbV2G
  (spot-check via the `decode` CLI, cover this in the regeneration script too).

### 5. Follow up on documentation

- `README.md`: rewrite the "What green means today" section — green now means
  wire conformance against cbV2G@<sha>. Update "Next milestones".
- `REPLACING_SEED_VECTORS.md`: switch from "planned" to "done",
  document the regeneration instructions (one command).
- If a Python simulator lives in the repo: delete it (per the docs it was only bootstrap
  scaffolding). If it's not in the repo: adjust the README note accordingly.

## Guardrails

- Only change the C# codec's wire semantics based on a concrete diff against
  cbV2G output, never speculatively.
- No new mandatory dependencies for the normal test run: `dotnet test` must
  keep working without a C toolchain, Java, or network.
- External code (the libcbv2g clone) is NOT checked into the repo — only the CLI harness,
  the script, and the pinned SHA.
- Follow the repo's code style (thorough explanatory comments, records).
- Commit in small steps, only on a green build.
